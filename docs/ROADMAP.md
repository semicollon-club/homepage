# 개발 로드맵 & 진행 추적

세미콜론 공개 홈페이지의 개발 단계를 정의하고 진행 상황을 추적하는 문서입니다.
작업을 완료하면 체크박스를 갱신하고, 필요 시 항목을 추가하세요.

> **이 프로젝트의 정체성**: 단순한 동아리 소개 페이지가 아니라, **부원들이 실제 기술을 실험하고 운영해보는 실험장**입니다.
> 종료 시점이 명확한 완성형 프로젝트가 아니라 계속 진화하는 프로젝트이며,
> 공개 페이지 완성(1~4단계) 이후 백엔드·DB·인증 등으로 확장합니다(6단계).

## 진행 상태 표기

- `[ ]` 예정 · `[~]` 진행 중 · `[x]` 완료

## 사이트의 목표

1. **신입 모집** — 방문자 대다수는 가입을 고민하는 학생
2. **활동 증명** — 학교·외부에 "실제로 활동하는 동아리"임을 보여주는 아카이브
3. **정보 제공** — 공지, 일정, 연락처
4. **기술 실험장** — 로그인·보안·데이터 관리 등 실무 기술을 직접 구현·운영하며 배우는 플랫폼

## 사이트맵 (공개 페이지 목표 구조)

```
/                  랜딩 (요약 + 각 페이지 진입 허브)
├─ /about          동아리 소개
├─ /organization   조직도 ✅
├─ /activities     활동 소개 (스터디·프로젝트·행사)
├─ /recruit        가입 안내 (절차·FAQ·지원 버튼)
├─ /projects       프로젝트 아카이브 (2차)
├─ /notice         공지·소식 (2차)
├─ /members        부원 소개 (2차, 본인 동의 필수)
└─ 404             잘못된 주소 안내
```

**아직 만들지 않는 것**: 로그인, 관리자 페이지, DB 연동. 프론트 단독 단계에서는 구글폼 링크와 `src/data/*.ts` 파일로 처리하고, **6단계 실험 트랙에서 백엔드와 함께 도입**합니다. (지금 데이터를 `src/data/`로 분리해두는 것이 나중에 API로 교체하는 자연스러운 진화 경로가 됩니다.)

## 6단계. 실험 트랙 — 백엔드·DB·인증 (공개 페이지 안정화 이후, 상시 진화)

> 목적은 "기능 완성"이 아니라 **기술을 직접 겪어보는 것**입니다. 실패해도 배우면 성공입니다.
> 단, 실험이 실서비스(공개 페이지)를 깨면 안 됩니다 — 아래 안전 원칙을 지킵니다.

실험 후보 (팀 논의로 선정·순서 결정):

- [x] 백엔드 API 서버 — asahi 저장소 `server/` (Express 5 + TS), `api.semicollon.com`으로 배포
- [x] DB 기틀 — Supabase `web` 스키마·최소권한 role, **마이그레이션 러너**(배포 시 운영 자동 적용), dev DB 분리. ID는 UUIDv4로 시작
- [x] 회원 인증 — 회원가입/로그인 직접 구현 (bcrypt + DB 세션, httpOnly 쿠키)
- [~] 보안 기초 — 환경변수 분리·role 권한 분리·CORS 허용목록·zod 검증 적용됨. 남은 실험: rate limit, CA 고정 TLS, 만료 세션 정리
- [ ] 부원 전용 기능 — 로그인 후 공지 작성, 출석 체크 등 (실험에 실사용처를 부여)
- [ ] `/notice` 데이터를 data 파일 → DB API로 전환 (첫 프론트-백 연동 실험)
- [ ] 운영 경험 — 로그, 모니터링, 장애 대응

**실험 안전 원칙**

1. 실험도 동일한 규칙: 브랜치 → PR → CI → main(스테이징 검증) → production
2. 새 기술 도입 전 Decision Log에 "무엇을, 왜"를 한 줄 기록 (라이브러리 설치 규칙은 AGENTS.md 참조)
3. 공개 페이지의 핵심 경로(랜딩·모집)는 실험 실패의 영향권 밖에 둔다
4. 백엔드가 생기면 AGENTS.md·ARCHITECTURE.md를 반드시 함께 갱신
